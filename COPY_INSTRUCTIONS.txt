PHASE 17A.1 — Live Support Conversation Creation Fix

ROOT CAUSE
The Phase 17A migration created support_conversations and support_messages,
but service_role did not receive table privileges.

The server-side support API uses createSecretServerClient(), so the database
rejected conversation/message inserts even though the tables and RLS existed.

FIX
Grant SELECT, INSERT, UPDATE and DELETE on:
- public.support_conversations
- public.support_messages

ONLY to:
- service_role

SECURITY
- anon is NOT granted access.
- authenticated is NOT granted access.
- RLS remains enabled.
- Visitor/customer access still goes exclusively through the server-side API.

HOW TO APPLY
1. Copy the supabase/ folder into the project root.
2. Apply:
   supabase/migrations/20260904001500_live_support_service_role_grants.sql
3. Commit/push normally.

No frontend files need replacement.

RECOMMENDED COMMIT
fix: grant service role access to live support tables
