BOOSTINGPEDIA — PHASE 19 DIRECT CHECKOUT AFTER ORDER CREATION

GOAL
After a customer configures a service and creates the order, do not show the
inside of the order before payment.

NEW FLOW
Configure service
→ Create order
→ Direct secure Stripe Checkout
→ Successful payment
→ Customer order workspace

BEHAVIOR
- Newly created orders with:
  status = pending_payment
  AND paymentStatus = unpaid or failed
  are immediately sent to the existing /api/checkout Stripe flow.
- The CustomerOrderWorkspace is NOT loaded before checkout.
- If Stripe returns checkout=success, checkout=cancelled, or paymentError,
  the automatic redirect is skipped so existing post-checkout behavior remains intact.
- Booster mode is unchanged.
- Existing Stripe checkout route is unchanged.
- Pricing, order creation, order snapshots, dashboard, chat, presence,
  Secure Account Access, evidence, lifecycle and permissions are unchanged.
