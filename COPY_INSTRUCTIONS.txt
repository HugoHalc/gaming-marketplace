PHASE 17A — Admin Live Support Foundation

PURPOSE
Add a global pre-sale Live Support Chat for:
Website Visitor / Customer <-> Admin

There is NO support-staff role in this phase.
Only users with profiles.role = 'admin' can read and answer support conversations.

IMPORTANT ORDER OF INSTALLATION
1. Copy the src/ and supabase/ folders from this ZIP into the project root.
2. Apply the included Supabase migration:
   supabase/migrations/20260903130100_admin_live_support_foundation.sql
3. Commit/push to GitHub.
4. Allow Vercel to deploy normally.

WHAT IS INCLUDED

PUBLIC / CUSTOMER
- Global floating Live Support button in the bottom-right corner.
- Available across the website except /admin pages.
- Visitors can start a conversation without logging in or purchasing an order.
- Signed-in customers are linked to their existing identity automatically.
- Anonymous session stored with a secure HttpOnly cookie.
- Messages persist across page navigation and browser refreshes.
- Unread admin replies display on the floating button.
- Conversation can be reopened by sending a new message after it was closed.
- Mobile-safe positioning and responsive support window.

ADMIN
- New protected page: /admin/support
- Protected by existing requireAdmin().
- Open / Closed conversation filters.
- Conversation queue with unread counts.
- Active conversation panel.
- Admin replies as "BoostingPedia Support".
- Close and reopen conversations.
- Live synchronization via short secure polling.
- Link to Live Support added to current /admin page.

SECURITY
- support_conversations and support_messages have RLS enabled.
- No browser-access RLS policies are created.
- Visitor access is validated server-side with a random session token stored only as a SHA-256 hash in the database.
- Admin access is validated server-side by requireAdmin().
- Browser clients never receive the Supabase secret key.
- Visitor messages are limited to 1500 characters.
- Basic per-conversation anti-spam limit: max 12 visitor messages per minute.

DATABASE
Creates:
- public.support_conversations
- public.support_messages

This migration IS REQUIRED.

REALTIME NOTE
Phase 17A intentionally uses short polling rather than exposing anonymous Supabase Realtime access.
Visitor open chat: refresh approx. every 3.5 seconds.
Admin active chat: refresh approx. every 3 seconds.
This keeps anonymous conversations private and gives near-live behavior without weakening RLS.
Realtime can be upgraded later if desired.

NOT CHANGED
- order_messages / order live chat
- auth roles
- booster assignment
- checkout/payment
- customer dashboard order logic
- Secure Account Access
- order lifecycle
- notifications
- existing RLS
